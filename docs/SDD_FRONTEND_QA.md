# Frontend QA component boundaries

`frontend_qa.py` owns terminal prompts, target URL validation, runner selection, deterministic key-name matching, static page inspection, artifact writing, and report opening. Local Laya is the default guided-exploration runner; Jev is selected explicitly as a separate comparison/alternate arm. Missing Laya fails closed. Provider names map to fixed environment-variable families.

Targets are already reachable HTTP(S) URLs. For local work, the operator starts the app stack and supplies its localhost URL. The CLI does not accept a target repository path, inspect its package scripts, start/stop project services, or read target `.env` files. Playwright is the browser substrate for whichever guided-exploration runner is selected; deterministic assertions support the evidence and do not replace model-driven exploration. Vision is an independent optional module and defaults off; this PC's local option is 2B-class and hosted option is 4B-class. The Jev `.env` remains the only credential store.

The report contains an inline SVG timeline and no external dependencies. `workflow.mmd` is the portable source graph. Each link check and response is an observed event; a defect node points to findings in the same report.

The Laya adapter follows the published local Python contract: `from laya import Router`, then `Router().predict(state, questions)`. Install the optional `laya` extra in the same Python environment to make it available. The upstream package loads model checkpoints on first prediction. The implementation environment had neither the package nor executable installed, so only the injected-router contract test ran; the CLI now defaults to Laya and fails closed when the runtime is missing. The browser exploration loop and two requested live acceptance targets remain unimplemented/untested. See the [Laya package instructions](https://github.com/haddock-development/laya_new#installation-details) and [router quickstart](https://github.com/haddock-development/laya_new#quickstart-route-mode-recommended).

OpenCode's [server command](https://opencode.ai/docs/server/) starts its own HTTP API and OpenAPI description; it does not expose this repository's typed-decision schema. A future adapter needs a tested structured-output bridge that maps model output to the existing validated choice schema. The CLI must not present OpenCode as a working decision backend merely because its server is running.
